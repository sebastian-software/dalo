Your team’s agent skills, versioned like code.

Dalo keeps your team's agent skills in Git: one approved set, resolved the same way on every machine and reviewed before it reaches any agent folder.

brew install sebastian-software/tap/dalo curl -fsSL https://dalo.sh/install.sh | sh npx getdalo --version

Workflow

From local experiment to team standard.

Start with one skill an agent wrote on your laptop. End with the whole team resolving the same reviewed set.

  1. 1

    Adopt

    An agent wrote a useful skill straight into its folder. Dalo copies it into your local source first; the original stays untouched.

    dalo adopt review-helper
  2. 2

    Add a source

    Connect the team repo. Its dalo.toml can compose commit-pinned catalogs, so everyone resolves the same selection.

    dalo source add company git@github.com:acme/agent-skills.git
  3. 3

    Review & approve

    Read the evidence, then record the decision. Approvals are source-qualified and live in your own store.

    dalo audit company:release-helper
    dalo approve skill company:release-helper
  4. 4

    Sync

    Resolve every source into one set and link it into your agent folders. Safe to run any time.

    dalo sync
Fair question

Why not just…

…copy the folder around?

Works for one laptop. Then versions drift and nobody knows which copy is current.

Dalo pins exact commits and resolves the same set on every machine, recorded in a lockfile.

…symlink a shared repo by hand?

Fine until a link clobbers someone's real folder, or a pull eats an uncommitted edit.

Dalo removes only links it owns, never overwrites unmanaged folders, and blocks on dirty checkouts.

…use skills.sh or agentfiles?

Both are good at what they do: skills.sh for discovering public skills, agentfiles for an Obsidian UI.

Dalo covers the team side: exact pins, explicit approval, and sync that never takes over what it didn't make.

FAQ

Good questions.

What happens to skills already sitting in my agent folders?
Nothing. Dalo never overwrites unmanaged files or real folders; status lists them as unmanaged. When you want one under management, dalo adopt <skill> copies it into your local source and leaves the original in place unless you pass --replace.
Does a passing preflight mean a skill is safe?
No, and Dalo doesn't claim it does. The 15 deterministic rules catch known risky patterns and block high or critical findings until you record a content-bound risk acceptance. An optional sandboxed reviewer (Codex, Claude, or OpenCode CLI) can add findings but never clears one. Reading the skill is still your job.
Is there a daemon or a server?
No. Dalo is a single Rust binary that needs git on your PATH. If you want scheduled syncs, dalo autosync install uses launchd on macOS or a systemd user timer on Linux, and those runs never grant approvals.
Which platforms and agents are supported?
macOS on Apple Silicon and Linux on x86_64 and ARM64. Verified agents are Codex, Claude Code, OpenClaw, Hermes, and OpenCode; any other folder-based agent works with dalo target link generic <path>.
Will an upgrade break my store?
Stores written by 0.6.0 or later open with no migration command and no re-approval. Persisted schema changes are versioned and documented in the spec.
Can my agent install and set up Dalo itself?
Yes. Point it at dalo.sh/install.md or /llms.txt. Approvals still need you.
