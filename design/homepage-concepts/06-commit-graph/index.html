feat(store): one source of truth in ~/.dalo

Local skills, team repositories and public catalogs are checked out into one store, next to the locks, trust decisions and audits that describe them. The store decides; agent folders only receive.

That boundary keeps team repositories clean, local experiments private, and anything already on disk safe to inspect.

feat(adopt): keep what your agent wrote

Your agent just wrote a useful release-notes skill straight into ~/.claude/skills. Dalo notices it, leaves it alone, and tells you how to keep it.

dalo adopt runs the security preflight, copies the skill into your private local source and, with --replace, swaps the original folder for a link Dalo owns. The experiment starts here, on your machine only.

feat(source): add the team repository

A team source is a Git repository with a skills/ folder. Adding it is the trust decision: Dalo clones it, discovers the skills and audits every one before anything is linked.

Edit a team skill in place and the checkout is dirty, so the next refresh stops for it instead of discarding your change.

feat(resolve): same inputs, same set

The resolver is a pure function: same sources and config, byte-for-byte the same result on every machine. Same-name conflicts go by priority, and the lower number wins.

So while you iterate, your local copy holds the slot and the team's older release-notes stays visible as shadowed, never silently dropped.

merge: promote release-notes to the team

Promotion is a pull request, not a Dalo feature. Dalo never commits adopted work for you: when the experiment has proved itself, it goes into the team repository and through the review you already run.

Once it merges, retire your local copy. The next sync relinks the slot to the team version, and every teammate resolves the same thing.

fix(sync): never overwrite what you didn't create

Dalo may manage what it owns. It does not take ownership by surprise.

If a real folder already holds a slot, sync reports the conflict and leaves it exactly where it is. Dalo removes only links it created, and --dry-run prints the same plan a real run would execute, writing nothing.

feat(team): pin catalogs to exact commits

A team repository can compose public catalogs into its own set. dalo team catalog add writes an immutable commit into the checked-in dalo.toml, so upstream moving on changes nothing until you move the pin.

+copywriting includes, -seo-audit excludes, and skills = [] selects everything. Every teammate resolves the same declared selection.

0d5f3e7

feat(preflight): review before delivery

Catalog skills arrive as offers, not installs. Fifteen deterministic rules run locally before any link is created; high or critical findings block until someone records an explicit, content-bound risk acceptance.

An optional sandboxed agent reviewer (Codex, Claude or OpenCode CLI) can add findings but never clears one. Approvals are per skill, bound to exact content, and never granted by a sync.

A clean preflight means no known issue was detected. It is not a safety guarantee, and Dalo says so in its own output. Read the security model.

docs: compare skills.sh and agentfiles

skills.sh is great for discovering public skills and installing them into almost any agent. agentfiles puts agent files into an Obsidian UI.

Dalo covers the team side: exact commit pins, explicit approval, and sync that never overwrites unmanaged folders. Find a skill on skills.sh, then let Dalo pin and deliver it.
