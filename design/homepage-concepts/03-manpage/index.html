NAME

dalo — your team's agent skills, versioned like code

SYNOPSIS

dalo [--store path] [--json] [--dry-run] command [argument...]
dalo target link target [path]
dalo source add id git-url-or-path
dalo sync [--check]
dalo approve skill source:skill

DESCRIPTION

dalo keeps your team's agent skills in Git: one approved set, resolved the same way on every machine and reviewed before it reaches any agent folder.

It is for engineers and team leads who run Claude Code, Codex, or another agent across several people and machines, and want all of them working from the same reviewed skills.

Skills come from sources: your private local source, team Git repositories, and public catalogs. dalo gathers them in a store at ~/.dalo, runs a security preflight, waits for approval where one is required, resolves one set, and links it into the folders your agents already read. The store is the source of truth; agent folders are only output targets.

local    prio  0 ----.
company  prio 10 ----+---> ~/.dalo      sources · locks · trust · audits
oss      prio 20 ----'        |
                              v
                          preflight     15 rules, then your approval
                              |
                              v
                          resolver      same inputs, same bytes
                              |
                              v
                      ~/.claude/skills  owned symlinks only
                      ~/.agents/skills

local    prio  0 --.
company  prio 10 --+--> ~/.dalo
oss      prio 20 --'       |
                           v
                       preflight
                           |
                           v
                       resolver
                           |
                           v
                   ~/.claude/skills
                   ~/.agents/skills

The resolver is a pure function: the same inputs give a byte-for-byte identical result. When two sources ship a skill with the same name, source priority decides and the lower number wins; the others are reported as shadowed, never silently dropped.

One Rust binary, no daemon, nothing to host: dalo only needs git on your PATH. It runs on macOS (Apple Silicon) and Linux (x86_64, ARM64).

QUICK START

Create the store, point dalo at an agent, add your team's repository, and sync:

dalo initdalo target detectdalo target link codexdalo source add company git@github.com:acme/agent-skills.gitdalo syncapplied create target[codex]:/incident-review -> store:/sources/company/checkout/skills/incident-reviewapplied create target[codex]:/release-notes -> store:/sources/company/checkout/skills/release-notessynced: 2 skills across 1 target (2 created)security preflight: deterministic checks onlydalo status

Link more agents the same way, dalo target link claude, and the next sync delivers the same set there too.

Skills from a public catalog wait until you select them, read the audit, and approve:

dalo source add-catalog sebastian https://github.com/sebastian-software/skills.sebastian-software.com.gitdalo source select sebastian effective-webdalo syncsynced: 2 skills across 1 target (2 unchanged)pending approval: sebastian:effective-web (run: dalo approve skill sebastian:effective-web)dalo audit sebastian:effective-webdalo approve skill sebastian:effective-webdalo sync

COMMANDS

The ones you will reach for most. Each accepts --help; the command reference has the rest.

Setup

init
Create the store: config, local Git source, lock, and approvals.
next
Summarize the store and print one copyable next action.
target detect
List known agents, their skill folders, and what is linked.
target link target [path]
Record an agent folder as a target; generic takes any path.

Sources

source add id git-url-or-path
Add a team Git repository or a local path as a source.
source add-catalog id git-url-or-path
Add a public catalog; nothing in it activates until selected.
source select id skill...
Select catalog skills, pinned to an exact commit.
source priority id priority
Decide which source wins a same-name conflict; lower wins.
team catalog add id git-url-or-path --version revision
Pin an external catalog in the team's dalo.toml.

Delivery

sync [--check]
Audit, resolve, and link the approved set into every target.
status [--check]
Show sources, targets, skills, approvals, drift, and conflicts.
adopt skill [--replace]
Copy a skill an agent wrote into your local source to manage it.
instructions enable pack-ref file
Render a managed block; everything outside it stays yours.
autosync install
Sync on a schedule via launchd, systemd, or cron. Never approves.

Review

audit skill-or-path
Run the security preflight and show the evidence.
approve skill source:skill
Record an explicit, source-qualified approval.
approve list
Show recorded approvals; approve revoke takes one back.

Health

doctor [--check]
Read-only diagnostics; every finding names its fix.
completions shell
Print completions for bash, zsh, fish, and others.
manpage
Print the real dalo(1) page, in roff, to stdout.

OPTIONS

Global options go before or after the command.

--store path
Use another store. Beats DALO_STORE, which beats ~/.dalo.
--json
Emit machine-readable JSON where a command supports it.
--dry-run
Plan supported mutating operations; write nothing.
-h, --help
Print command help.
-V, --version
Print the installed version.

SAFETY

One rule governs everything dalo writes:

Dalo may manage what it owns.
It does not take ownership by surprise.

  • It never overwrites unmanaged files, real folders, or foreign symlinks, and it removes only the links it created.
  • A dirty team checkout blocks the refresh instead of losing your edits.
  • Catalog skills need an explicit selection and an explicit approval. Autosync applies existing approvals; it never grants new ones.
  • Before a link is created, 15 deterministic rules run locally over every active skill. High or critical findings block until someone records a risk acceptance bound to that exact content.
  • An optional sandboxed agent reviewer (the Codex, Claude, or OpenCode CLI) can add findings. It can never clear one.
  • --dry-run prints the plan and writes nothing. Conflicts stay visible in dalo status until you resolve them.

A passing preflight is evidence for the person who approves, not a safety guarantee. The security overview lists every guarantee and its limits.

FILES

The store lives in ~/.dalo unless --store or DALO_STORE says otherwise.

~/.dalo/config.toml
Your settings and source list.
~/.dalo/lock.toml
The resolved set, written by sync.
~/.dalo/approvals.toml
Local approval records.
~/.dalo/audits/
Security reports, bound to content.
~/.dalo/local/skills/
Your private skills, tracked in Git.
~/.dalo/sources/id/checkout/
Team and catalog Git checkouts.

A team repository can carry a dalo.toml manifest that pins external catalogs and filters them: +copywriting includes, -seo-audit excludes, and skills = [] selects all.

Agent folders are output targets. dalo links into these by default:

ENVIRONMENT

DALO_STORE
Store path; --store takes precedence.
DALO_GIT_TIMEOUT_SECS
Timeout in seconds for every Git subprocess.
DALO_OFFLINE
Any truthy value disables passive update checks.
DALO_UPDATE_CHECK
Set to never to disable passive update checks.
DALO_INSTALL_CHANNEL
Set by launchers; picks the upgrade command shown.
NO_COLOR
Disables ANSI color output.

Installer variables such as DALO_TARGET and DALO_VERSION are read only by install.sh; see install.md.

EXIT STATUS

0
Success.
1
Expected failure: input or state you can act on, a failed --check, or a security block during sync or approve.
2
Usage error: invalid arguments or flags.
3
Unsafe state: dalo refused to mutate because something needs a human, such as a dirty source, an active store lock, or a malformed instruction block.
4
Environment problem: a dependency, path, Git, filesystem, or external command failed.

Scripts should treat 3 differently from 1: it means dalo stopped on purpose, before touching anything that may need review.

DIAGNOSTICS

Every blocking state names the next command to run, and a typo gets a suggestion instead of a dead end:

dalo synkerror: unrecognized subcommand 'synk' tip: a similar subcommand exists: 'sync'dalo approve skill company:relese-helpererror: skill `company:relese-helper` was not found; did you mean `company:release-helper`?; known skills: company:new-skill, company:release-helper

dalo doctor inspects the store, config, locks, approvals, Git, targets, owned links, and dirty sources without changing anything, and reports findings, each with a fix. dalo doctor --check exits 1 on any error finding, for CI.
