01

The problem

operational knowledge, unmanaged

Skills drift across machines.

Agent skills encode how your team works. But most of them still live in one machine's folder, a pasted snippet, or a chat thread. Over time, versions diverge, ownership blurs, and the same skill behaves differently for everyone.

The usual flow

  1. install this skill here
  2. copy that folder there
  3. pick the target agent again
  4. hope nobody changed the public repo
  5. hope the local edit doesn’t get lost
  6. hope the team runs the same version

With Dalo

  • 1.1Every skill versioned in Git
  • 1.2Resolved deterministically
  • 1.3Synced across the whole team
  • 1.4Private work kept separate
  • 1.5Existing files never touched
  • 1.6Ready to promote when it proves out

The model

many sources → one reviewed set

Many sources in. One reviewed set out.

  1. 2.1

    Sources

    Local skills, team Git repositories, and public catalogs you select from.

  2. 2.2

    Store

    The source of truth: sources, locks, trust, and audits.

    ~/.dalo

  3. 2.3

    Preflight + approval

    15 deterministic rules, run locally. Catalog skills wait for your explicit approval.

  4. 2.4

    Resolver

    A pure function. Same inputs, byte-for-byte the same result.

  5. 2.5

    Agent folders

    Symlinks into the directories your agents already read. Outputs, never the database.

    ~/.agents/skills
    ~/.claude/skills
    ~/.hermes/skills

The store is the source of truth. Agent folders are output targets.

03

Resolution by priority

same name “review” · one slot

Lower number wins. Everyone else is shadowed.

  1. 0
    localprio 0
    linked
  2. 10
    companyprio 10
    shadowed
  3. 20
    ossprio 20
    shadowed

When two sources ship a skill with the same name, source priority decides which one fills the slot. The lower number wins.

Losers are reported as shadowed in dalo status — visible, never silently dropped.

The resolver is a pure function: the same sources and config give a byte-for-byte identical result on every machine.

04

Safety rules

conservative on purpose

The core rule.

Dalo, rule zero

applies to every command

Dalo may manage what it owns. It does not take ownership by surprise.
  1. 1

    Never overwrites unmanaged files

    If a real skill folder already holds a slot, Dalo reports the conflict and leaves it exactly where it is.

  2. 2

    Removes only links it owns

    Resolved skills are directory symlinks. Dalo removes only the links it created.

  3. 3

    Dirty work blocks, not breaks

    Edited a team skill in place? The checkout is dirty, and refresh stops instead of discarding your change.

  4. 4

    Catalog skills need approval

    Each catalog skill stays an offer until you select it and run dalo approve skill.

  5. 5

    --dry-run everywhere

    The same planning path drives real runs and dry runs. See every link before anything changes.

  6. 6

    Conflicts stay visible

    dalo status explains every state. Nothing is forced, nothing is hidden.

15

Deterministic rules run locally before a link is created.

High and critical findings block until someone records an explicit, content-bound risk acceptance. An optional sandboxed agent reviewer — Codex, Claude, or the OpenCode CLI — can add findings, but never clears one.

A passing preflight is not a safety guarantee. It makes the decision to run a third-party skill explicit, reviewable, and reproducible.

07

Compared

where the usual tools stop

Why not just install skills directly?

  1. 7.1

    One-off installer

    Good for one machine.

    Weak once a team needs review, shared versions, and the same result on every laptop.

  2. 7.2

    Dotfile repo

    Too broad for agent skills.

    Great for personal setup, risky when skill rollout can overwrite unrelated environment files.

  3. 7.3

    Git submodule

    Pins a repo, not a selection.

    Awkward for catalogs where you only want three skills out of forty.

  4. 7.4

    Copy-paste

    Fast until nobody knows what changed.

    No drift detection, no provenance, no path from local experiment to team standard.

Dalo covers the team side

Find a skill on skills.sh, then let Dalo pin and deliver it.

  • Exact commit pins in lockfiles
  • Explicit approval before delivery
  • Sync that never overwrites unmanaged folders

skills.sh is great for discovering public skills and installing them into almost any agent; agentfiles puts agent files into an Obsidian UI. Read the full comparison.
