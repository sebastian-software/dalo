Prefer commands? Follow the CLI guide
Or try the CLI in a throwaway sandbox

No CLI yet? Use npx getdalo in place of dalo, and unset DALO_STORE SKILLS_DIR when you're done.

first sync
# sandbox: no real agent folders touched
$ export DALO_STORE="$(mktemp -d)/store"
$ export SKILLS_DIR="$(mktemp -d)/skills"
$ dalo init
$ dalo target link generic "$SKILLS_DIR"
 
# try a real public catalog
$ dalo source add-catalog sebastian https://github.com/sebastian-software/skills.sebastian-software.com.git
$ dalo source inspect sebastian
$ dalo source select sebastian effective-web
$ dalo audit sebastian:effective-web
$ dalo approve skill sebastian:effective-web
$ dalo sync
security preflight: deterministic checks only

Not starting from zero?

Dalo leaves existing folders alone until you decide.

  • Skills already in an agent folder

    Ask: “Move my existing skills to Dalo and keep my changes.” Adopt a skill

  • A project that uses skills.sh

    Ask: “Move this project from skills.sh to Dalo.” Migration guide

  • Skills for one repository

    Ask: “Give every clone of this repo the same skills.” Project installations

  • A team sharing skills

    Ask: “Connect our team's skill repository.” Catalog approvals stay on each machine. Team repository guide

One source of truth

One pinned set. Every machine.

Skills sit at an exact Git commit until you advance the pin. Then every machine gets the same version.

Reviewed first

Review skills before they reach an agent.

Your agent explains a skill before you trust it. Dalo checks every skill against fifteen local security rules, and catalog skills, tools, and hooks wait for your approval.

Read the security model
Safe by default

Only touches what it owns.

Sync updates only the links and managed blocks Dalo owns. Your own files stay put, and conflicts wait for your call. Want a preview? Ask for a --dry-run.

Early, and used every day.

Dalo is v1.10.0, and we run it on our own machines every day. Sources, deterministic resolution, security audits and review gates, safe sync, and diagnostics have shipped under the 1.x compatibility contract. That contract and the security model also say what Dalo doesn't promise.

Who it's for

  • Teams sharing skills across people and machines
  • Anyone who wants exact pins and a review step before a skill reaches an agent
  • People who'd rather talk to their agent than learn a CLI

Not (yet) for

  • Native Windows (WSL works)
  • Finding skills: browse skills.sh, then pin your picks with Dalo
  • A one-off try: npx skills is quicker

Get it wrong. Dalo gets you back.

Typos get a suggestion, and a blocked sync names the command that unblocks it.

recovery, not dead ends
$ dalo synk
error: unrecognized subcommand 'synk'
  tip: a similar subcommand exists: 'sync'
 
$ dalo approve skill company:relese-helper
error: skill `company:relese-helper` was not found; did you mean `company:release-helper`?; known skills: company:new-skill, company:release-helper
 
$ dalo sync
dalo store: ~/.dalo
nothing materialized: resolution is incomplete
  pending approval: sebastian:effective-web (run: dalo approve skill sebastian:effective-web)
