One binary into ~/.local/bin, no sudo. The SHA-256 checksum is always verified, Sigstore provenance when cosign is installed. Installer source · Uninstall guide · Windows via WSL.

One agent setup per laptop, and nobody knows which skills were reviewed.

A skill is a folder with a SKILL.md that teaches an agent one job. Teams collect dozens of them, copied from the internet and edited by hand, until every machine runs a different set. Dalo keeps one reviewed set in Git and delivers it to every agent: the skills, the instructions that go with them, and the hooks that run at the right moment.

Safe by default

Only touches what it owns.

During sync, Dalo leaves your own files and folders in place. It updates only the links and managed content it owns, and reports conflicts that need your decision. Ask your agent to preview changes with --dry-run.

Dalo may manage what it owns. It does not take ownership by surprise.

Try the CLI in a throwaway sandbox

Install the binary first with the terminal instructions above. npx getdalo also runs it without a global install. These commands use temporary folders. Afterwards, unset DALO_STORE SKILLS_DIR returns your shell to your real setup.

first sync
# sandbox: no real agent folders touched
$ export DALO_STORE="$(mktemp -d)/store"
$ export SKILLS_DIR="$(mktemp -d)/skills"
$ dalo init
$ dalo target link generic "$SKILLS_DIR"
 
# try a real public catalog
$ dalo source add-catalog sebastian https://github.com/sebastian-software/skills.sebastian-software.com.git
$ dalo source inspect sebastian
$ dalo source select sebastian effective-web
$ dalo audit sebastian:effective-web
$ dalo approve skill sebastian:effective-web
$ dalo sync
security preflight: deterministic checks only

Not starting from zero?

Pick the situation that matches yours. Dalo leaves existing folders alone until you decide.

  • Skills already in an agent folder

    Ask: “Check my existing skills and bring them under Dalo. Keep my changes.” Your agent inspects them first and explains the adoption plan. Adopt a skill

  • A project that uses skills.sh

    Ask: “Move this project's skills.sh setup to Dalo.” Dalo checks installed copies against their sources; your agent explains any differences that need a decision. Migration guide

  • Skills for one repository

    Ask: “Set up Dalo for this repository so every clone gets the same skills.” A committed project definition pins the set, with a separate store in each clone. Project installations

  • A team sharing skills

    Ask your agent to connect your team's skill repository. Everyone draws from the same Git source; catalog approvals stay on each machine. Team repository guide

Get it wrong. Dalo gets you back.

Typos get a suggestion, unknown skills get the list of known ones, and a blocked sync prints the exact command that unblocks it.

recovery, not dead ends
$ dalo synk
error: unrecognized subcommand 'synk'
  tip: a similar subcommand exists: 'sync'
 
$ dalo approve skill company:relese-helper
error: skill `company:relese-helper` was not found; did you mean `company:release-helper`?; known skills: company:new-skill, company:release-helper
 
$ dalo sync
dalo store: ~/.dalo
nothing materialized: resolution is incomplete
  pending approval: sebastian:effective-web (run: dalo approve skill sebastian:effective-web)
