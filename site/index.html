Quickstart

Up and running in minutes.

Try Dalo against a real public catalog in a throwaway sandbox. Nothing touches your agent folders, and every command takes --dry-run.

Also installs with cargo install dalo, cargo binstall dalo, mise, or npx getdalo. Installing through an agent? Point it to install.md.

Read the getting started guide
first sync
# sandbox: no real agent folders touched
$ export DALO_STORE="$(mktemp -d)/store"
$ export SKILLS_DIR="$(mktemp -d)/skills"
$ dalo init
$ dalo target link generic "$SKILLS_DIR"
 
# try a real public catalog
$ dalo source add-catalog sebastian https://github.com/sebastian-software/skills.sebastian-software.com.git
$ dalo source inspect sebastian
$ dalo source select sebastian effective-web
$ dalo audit sebastian:effective-web
$ dalo approve skill sebastian:effective-web
$ dalo sync
security preflight: deterministic checks only

Everything else a team needs

Shipped, documented, and covered by the same tests as the core.

  • Security preflight and review gate

    15 deterministic rules run before any link is made; high findings block until an explicit, content-bound exception. Security model

  • Team catalogs

    dalo team catalog add pins a commit; +copywriting includes, -seo-audit excludes, skills = [] selects all. Team guide

  • Instruction packs

    Shared conventions as versioned Markdown, rendered into managed blocks. Everything outside the markers stays yours.

  • Scheduled autosync

    dalo autosync install keeps folders current via launchd, systemd, or cron. Scheduled runs never grant new approvals.

  • Portable plugins

    Tools and hooks ship in PLUGIN.toml, each approved by the SHA-256 of its exact contract. Read the spec

  • Diagnostics

    dalo doctor checks store structure, lockfiles, Git availability, target paths, and broken symlinks.

Why not install skills directly?

Installers are great for trying one skill. Dalo is for the team that has to review, pin, and roll it out.
